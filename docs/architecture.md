# Архитектура FinTrack

## Подход

Приложение использует MVVM и разделяется на слои `data`, `domain` и `presentation`. На первом этапе весь код находится в модуле `app`. Пакеты создаются по мере появления кода. Пустые классы и файлы-заглушки не добавляются.

## Presentation

Слой содержит Compose-экраны, ViewModel и состояние интерфейса. ViewModel получает данные через use cases и предоставляет состояние экрана через `StateFlow`.

## Domain

Слой содержит доменные модели, интерфейсы репозиториев и необходимые use cases. Domain не зависит от Android, Compose и Room.

## Data

Слой содержит реализации интерфейсов репозиториев, Room DAO, Entity и преобразование моделей. Room является источником истины для сохранённых операций.

## Правила работы с данными

- Денежные суммы хранятся в `Long` в копейках.
- `Double` не используется для денежных расчётов.
- Room является источником истины для сохранённых операций.
- `StateFlow` представляет состояние экрана.
- Итоги вычисляются из операций.
- Разница доходов и расходов за период не считается фактическим остатком без учёта начального остатка.
